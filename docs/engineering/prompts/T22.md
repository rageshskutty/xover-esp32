# T22 — Constant-time upload token comparison

**Objective:** compare two already-bounded token buffers without content-dependent early exit.
**Paths:** `firmware/components/xoweb/internal/xoweb_auth.c`, `firmware/components/xoweb/internal/xoweb_auth.h`, `host/tests/test_token_auth.c`, host test registration only.
**API:** `int xoweb_token_equal(const uint8_t expected[32], size_t expected_len, const uint8_t provided[32], size_t provided_len);` Each pointer addresses exactly 32 readable bytes, padded by caller; lengths are 1..32. Return 1 only for equal length and equal bytes within those lengths, else 0. Bytes at indices greater than or equal to each buffer's length are padding and do not affect equality. Null, empty or >32 lengths return 0. Never call strlen on untrusted input. The caller rejects an oversized header before copying it into the fixed buffer.
**Constant-time rule:** for non-null buffers, always read and process all 32 byte positions, accumulating only content differences within the compared token length plus the length difference; do not return early on a content mismatch. Padding contents are ignored. A final result branch is allowed. No allocation or logging. Fixed loop bound is independent of token contents and lengths.
**Regression:** Do not modify registered tests; the full host suite must stay green.
**Test:** committed unregistered `host/tests/test_token_auth.c`. Register, confirm expected missing-function baseline failure, implement. Cover equal token, first/last byte mismatch, different lengths with common prefix, length 32 equality and mismatch, length 0 and >32 on either side, null pointers, and equal tokens whose padding bytes differ. Tests cannot prove timing; the implementation must visibly follow the fixed 32-byte loop.
**Size:** 30–80 production LOC. Existing NVS/network token policy remains unchanged; do not expose the secret. Run focused/host tests and `python tools/check.py`; report unrun checks. Three attempts maximum, diff-only output.
