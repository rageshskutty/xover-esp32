# T07a1 — Protection curve comparator

**Objective:** implement ADR 0010's pure comparator only. This is host-testable C; no graph traversal, persistence, JSON, ESP-IDF, or hardware.
**Baseline:** branch `architecture/7b-plan-overhaul-v2`; T06b1 present.
**Dependencies:** ADR 0010 comparator contract and ADR 0011 public protection-type contract; human CODEOWNERS approval before merge.
**Exact paths:** `firmware/components/dspgraph/dspgraph_protect.c`, `firmware/components/dspgraph/internal/dspgraph_protect.h`, `firmware/components/dspgraph/include/dspgraph.h`, `docs/api.md`, `host/tests/test_protect.c`, `host/CMakeLists.txt`, `firmware/components/dspgraph/CMakeLists.txt`.
**Public type:** add exactly the `dspg_protect_t` declaration shown in `docs/api.md` §2.2 to public `dspgraph.h`; do not redeclare it in the internal header. Keep the comparator function and failure type internal as specified by ADR 0010. Update `docs/api.md` in the implementation PR so its public declaration matches the header.
**API:** use the exact comparator signature and types in ADR 0010. Implement no other public API.

**Normative behavior:** follow ADR 0008 and 0010 exactly. Reject zero outputs or zero frequencies. Validate every pointer, dimension, ID, frequency, response sample, and record before comparing any limit. Require unique output IDs and an exact one-to-one output/record ID mapping. The bijection vector outputs `{o,o}`, records `{o,p}` must reject. Reject any non-finite response sample. For every malformed-input failure, return -1 and zero all fields of a non-null failure struct (including empty `out_id`); never use NaN as a sentinel. Only after whole-input validation, compare in output order then ascending frequency. On a valid limit violation return -1 with the first violation; equality passes. Return 0 and zero failure on success.

**Tests first:** `host/tests/test_protect.c` is already committed and intentionally not registered in CMake. It includes public `dspgraph.h` for the protection record and internal `dspgraph_protect.h` for the comparator. First add its single registration to the existing host test list, run it, and confirm it fails against the baseline (expected: missing comparator implementation/header). Then implement production code until it passes. Do not weaken or edit the test. Keep comparator implementation at or below 80 LOC. The committed test covers empty input, non-finite response, failure contents for malformed input, validate-all-before-compare, ID bijection, bounds, boundaries, ordering, and nulls.

**Applicable rules:** AGENTS S2 fail closed; C2 numerical tests; C3 warnings/checks green; C5 public headers need ADR and docs/API update; V1 honest evidence. No hardware values.
**Acceptance:** focused test fails before implementation and passes after; host suite and `tools/check.py` pass; <=80 comparator production LOC. If scope exceeds this, stop and request split.
**Stop/escalate:** any public-header/API mismatch; no ability to prove expected failure; signature change required; >80 LOC; safety threshold ambiguity. Three implementation attempts maximum.
**Output:** diff-only summary, production LOC, focused/full commands and results, baseline failure, blockers/deviations. No full-file dump.
