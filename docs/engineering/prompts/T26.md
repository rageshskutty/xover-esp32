# T26 — Bring-up app: pin walk and I2C scan (target only)

**Objective:** firmware modes for checklist steps P2.4, P2.5 and P5.6 (`docs/prebringup.md`). Target-only code: it cannot be host-tested, so the result stays UNVERIFIED until the maintainer builds and runs it.
**Depends on:** `board_config.h` pin map (merged). Does not depend on T23 to T25.
**Paths:** `firmware/main/main.c`, `firmware/main/Kconfig.projbuild`, `firmware/main/CMakeLists.txt` (REQUIRES `driver`, add `Kconfig` only if the build needs it).
**Kconfig:** choice `XOVER_BRINGUP_MODE` with `NONE` (default), `PINWALK`, `I2CSCAN`; bool `XOVER_BRINGUP_PINWALK_MUTE` default n; int `XOVER_BRINGUP_MAX_DBFS` default -30 (range -120 to -30; used by later audio modes).
**Behavior:**
1. First statement of `app_main`: configure `XOVER_PIN_DAC_MUTE_N` as output and drive it low (muted), before any mode runs (AGENTS S2).
2. `PINWALK`: for each pin in `XOVER_PIN_I2S_MCLK, XOVER_PIN_I2S_BCLK, XOVER_PIN_I2S_WS, XOVER_PIN_I2S_DOUT, XOVER_PIN_I2C_SDA, XOVER_PIN_I2C_SCL, XOVER_PIN_ADMIN_LED` (and `XOVER_PIN_DAC_MUTE_N` last, only if `XOVER_BRINGUP_PINWALK_MUTE`): configure as push-pull output, drive high 3000 ms, drive low, log `PINWALK gpio=<n> high` and `PINWALK gpio=<n> low`, then return the pin to input. Also log `PINWALK button gpio0=<0|1>` once per step. Loop forever. Intended for Phase 2 with no DAC boards attached.
3. `I2CSCAN`: create an I2C master bus on port 0 with `XOVER_PIN_I2C_SDA`, `XOVER_PIN_I2C_SCL`, `XOVER_I2C_FREQ_HZ`, internal pull-ups disabled (the DAC boards carry them). Probe every address 0x08 to 0x77 with `i2c_master_probe` and a 50 ms timeout. Log `I2CSCAN found 0x<hex>` per hit. Then log `I2CSCAN PASS` if the hits are exactly `XOVER_DAC0_I2C_ADDR`, `XOVER_DAC1_I2C_ADDR`, `XOVER_DAC2_I2C_ADDR`, otherwise `I2CSCAN FAIL`. Repeat every 2000 ms.
4. `NONE`: log once and idle. No audio is started in any mode of this card.
**Rules:** pins and addresses come only from `board_config.h` (S1); no magic numbers (C4); no TODO without a task id. If an ESP-IDF API named here does not exist in v5.5.6, stop and report; do not guess a replacement.
**Evidence:** this environment cannot build ESP-IDF. Report `idf.py build` as UNVERIFIED unless run, and list the exact `idf.py` commands for the maintainer. Results of running it are entered by the maintainer in `docs/bringup-log.md`.
**Size:** 40–80 production LOC across the files above. Three attempts maximum; diff-only report.
