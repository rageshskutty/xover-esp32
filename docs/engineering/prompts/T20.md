# T20 — Config CRC and A/B slot selection

**Objective:** validate config slot headers and choose the active or fallback slot using pure host logic. No flash/NVS access.
**Paths:** `firmware/main/internal/config_slot.c`, `firmware/main/internal/config_slot.h`, `host/tests/test_config_slot.c`, host test registration only.
**Header format:** four 32-bit fields in order: `magic, version, length, crc32`; length is payload bytes. CRC covers exactly `length` payload bytes and excludes the header. CRC-32/ISO-HDLC (reflected polynomial 0xEDB88320, init/final XOR 0xFFFFFFFF); empty payload CRC is 0.
**Type/API:** `typedef struct { uint32_t magic, version, length, crc32; } config_slot_header_t;` `uint32_t config_crc32(const uint8_t *data, size_t length);` (NULL with nonzero length returns 0); `int config_slot_valid(const config_slot_header_t *, const uint8_t *payload, size_t capacity, uint32_t expected_magic, uint32_t expected_version);` returns 1 valid/0 invalid; `int config_slot_choose(const uint8_t valid[2], uint8_t active_slot);` returns active slot if valid, otherwise the other valid slot, otherwise -1. Active selector outside 0..1 or null validity array returns -1.
**Validation:** require non-null header/payload, length 1..capacity, expected magic/version match, CRC match. Do not write slots or change selector here. Caller writes inactive slot first and flips selector only after complete validation.
**Test:** committed unregistered `host/tests/test_config_slot.c`. Register, confirm missing-function baseline failure, implement. Assert CRC of `123456789` is `0xCBF43926`, empty payload is 0, valid/corrupt data, wrong magic/version, zero/oversize length, active preference, fallback, neither valid, invalid selector and nulls.
**Size:** CRC and selection only, 30–80 production LOC. No partition sizes, magic value or flash facts guessed; callers supply expected magic/version. Three attempts maximum. Run focused/host tests and `python tools/check.py`; state what was not run.
