# T18 — S7 gain-ramp duration helper

**Objective:** compute a safe sample count for a linear gain ramp used by start, stop, swap and fault paths. This helper does not perform audio processing.
**Authority:** AGENTS.md S7; 48 kHz from docs/design.md. Use existing `dsp_gain_set_target` to execute the returned ramp.
**Paths:** `firmware/components/dspblocks/dsp_s7_ramp.c`, `firmware/components/dspblocks/internal/dsp_s7_ramp.h`, `host/tests/test_s7_ramp.c`, host and component source registration.
**API:** `int dsp_s7_ramp_frames(float current, float target, uint32_t *frames);` Return 0 on valid arguments, -1 for null output, non-finite gains, or gains outside [0,1]. On failure leave `*frames` unchanged. Equal gains return 0 frames.
**Rule:** linear per-sample gain delta must be <=0.001 (a full-scale input step is therefore <= -60 dBFS). Ramp-up uses at least 960 samples (20 ms); ramp-down uses at least 240 (5 ms). Compute the delta in float32 exactly as written: `float delta = fabsf(target - current); uint32_t need = (uint32_t)ceilf(delta / 0.001f);` Return the greater of that count and the directional minimum. Do not compute this in double. Caller passes the result unchanged to `dsp_gain_set_target`. The helper does not decide whether an event is safe to begin.
**What is and is not guaranteed:** the 0.001f gate bounds the *commanded* step `delta/frames`. `dsp_gain_process` accumulates in float32 and snaps to target on the last frame, so the *observed* output delta can be larger: up to about 1.5 % over (0.0010148, -59.87 dBFS) in fuzzing, bounded by roughly `frames * 0.5 ulp(1.0f)`. The committed fixture asserts the observed delta is <= 0.0011f (10 % headroom). Do not describe this helper as guaranteeing <= -60 dBFS at the output. HUMAN DECISION OPEN: either accept the 0.0011f executor bound, or add headroom to the helper formula; the 7B must not make that choice. Division semantics: the 250/251 vectors need correctly rounded float32 division; verified on host only, UNVERIFIED on the ESP32-S3 toolchain.
**Numerical boundary:** all subtraction, absolute value, division, and ceiling use float32 (`fabsf`/`ceilf`) exactly as above. The per-sample bound is compared to the representable float constant `0.001f`; do not add an arbitrary decimal tolerance or change the safety gate. The test checks the 240-frame down-ramp minimum and the adjacent-float boundary around a 250-frame required ramp: `0.25f -> 0` yields 250, while `nextafterf(0.25f, INFINITY) -> 0` yields 251 under the specified float32 formula.
**Link:** the fixture also calls `dsp_gain_init`, `dsp_gain_set_target` and `dsp_gain_process`, so register it linked against `dspblocks` and `m`.
**Test:** committed but unregistered `host/tests/test_s7_ramp.c`. Register and confirm expected missing-function baseline failure. Assert 0->1 and 1->0 yield 1000 samples; 0.5->0.75 gives 960; 0.5->0.1 gives 400; 0.1->0.099 gives 240; 0.24->0 gives 240; 0.25->0 gives 250; nextafterf(0.25f, INFINITY)->0 gives 251; check the implied step <=0.001f and invalid/equal cases.
**Build:** host suite and `python tools/check.py`, existing strict flags. Production 30–80 LOC. Do not change existing `dsp_gain_t` layout or weaken S7. Three attempts maximum; report unrun checks honestly.
