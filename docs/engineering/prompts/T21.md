# T21 — Request size and structure bounds

**Objective:** implement a pure gate for already-counted HTTP JSON request dimensions.
**Paths:** `firmware/components/xoweb/internal/xoweb_bounds.c`, `firmware/components/xoweb/internal/xoweb_bounds.h`, `host/tests/test_request_bounds.c`, host test registration only.
**API:** `int xoweb_request_bounds_valid(size_t body_bytes, size_t json_depth, size_t node_count, size_t longest_string_bytes);` Return 1 if within limits, 0 otherwise.
**Limits (AGENTS X3):** body 1..32768 bytes, JSON depth 1..8 (root counts as depth 1), node count <=64 (zero passes this bounds-only gate; semantic validator decides whether graph is useful), every string <=32 bytes. This function performs no parsing and uses byte lengths, not character counts. Call this once before parsing with body length and placeholder dimensions (depth=1, nodes=0, string=0) to reject oversize/empty bodies without parsing; call it again after the bounded parser reports actual dimensions. The parser itself must also enforce depth and body ceilings. Run semantic validation only after both checks.
**Regression:** Do not modify registered tests; the full host suite must stay green.
**Test:** committed unregistered `host/tests/test_request_bounds.c`. Register, confirm expected missing-function failure, implement. Test minimum/maximum values and each individual limit just below/above, including 0 and SIZE_MAX body/depth/string. Ensure changing one dimension does not affect another.
**Size:** 30–80 production LOC. No allocation, HTTP, JSON library or hardware dependency. Do not relax AGENTS X3. Three attempts maximum; run focused/host tests and `python tools/check.py`, report actual outputs and diff only.
