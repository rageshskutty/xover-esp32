# T19 — Fail-closed application state machine

**Objective:** implement deterministic transitions for mute, run, swap and fault lifecycle. The caller executes the required gain ramps and owner acknowledgments.
**Paths:** `firmware/main/internal/app_state_machine.c`, `firmware/main/internal/app_state_machine.h`, `host/tests/test_app_state_machine.c`, host test registration only.
**States:** `SM_MUTED`, `SM_READY_MUTED`, `SM_RAMP_UP`, `SM_RUNNING`, `SM_RAMP_DOWN`, `SM_SWAP_WAIT`, `SM_FAULT_MUTED`.
**Events:** protection-valid/invalid, config-valid/invalid, start, stop, swap-request, ramp-done, swap-ack, swap-fail, fault. Store current state, protection/config validity, and pending ramp-down reason.
**Transitions:** initialize MUTED with both validity flags false and pending=NONE. Flag events update their flag before applying this table. A null state pointer or out-of-range event returns -1 unchanged. An event with no row below is ignored and returns 0 unchanged.

| Event | Current state / condition | Next state and pending reason |
|---|---|---|
| PROTECTION_VALID or CONFIG_VALID | MUTED; both flags now true | READY_MUTED |
| PROTECTION_VALID or CONFIG_VALID | Any other state | Unchanged |
| PROTECTION_INVALID or CONFIG_INVALID | RAMP_UP or RUNNING | RAMP_DOWN; pending unchanged |
| PROTECTION_INVALID or CONFIG_INVALID | READY_MUTED | MUTED |
| PROTECTION_INVALID or CONFIG_INVALID | Any other state | Unchanged |
| START | READY_MUTED; both flags true | RAMP_UP |
| STOP | RAMP_UP or RUNNING | RAMP_DOWN; pending=NONE |
| SWAP_REQUEST | RUNNING | RAMP_DOWN; pending=SWAP |
| SWAP_REQUEST | READY_MUTED; both flags true | SWAP_WAIT |
| FAULT | RAMP_UP or RUNNING | RAMP_DOWN; pending=FAULT |
| FAULT | RAMP_DOWN | RAMP_DOWN; pending=FAULT (fault overrides swap) |
| FAULT | MUTED, READY_MUTED, or SWAP_WAIT | FAULT_MUTED |
| FAULT | FAULT_MUTED | FAULT_MUTED (terminal) |
| RAMP_DONE | RAMP_UP; both flags remain true | RUNNING |
| RAMP_DONE | RAMP_UP; either flag false | RAMP_DOWN; pending unchanged |
| RAMP_DONE | RAMP_DOWN; pending=FAULT | FAULT_MUTED; clear pending |
| RAMP_DONE | RAMP_DOWN; pending=SWAP | SWAP_WAIT; clear pending |
| RAMP_DONE | RAMP_DOWN; pending=NONE; both flags true | READY_MUTED |
| RAMP_DONE | RAMP_DOWN; pending=NONE; either flag false | MUTED |
| SWAP_ACK or SWAP_FAIL | SWAP_WAIT; both flags true | READY_MUTED |
| SWAP_ACK or SWAP_FAIL | SWAP_WAIT; either flag false | MUTED |

Old graph validity on SWAP_FAIL is represented by the same protection and config flags; there is no extra field. No event may enter RUNNING without both flags true.
**Terminal decision:** `FAULT_MUTED` is latched for the lifetime of this state-machine instance. No runtime event, including new valid flags, START, SWAP_ACK, or RAMP_DONE, leaves it. Validity events still update their corresponding flags, but output stays fault-muted. Clearing the latch requires reinitialization after a system reset; `app_sm_init` starts at MUTED with both flags false, so fresh protection and config validation are required before READY_MUTED or RUNNING. This fail-closed terminal policy requires explicit human safety review before implementation.
**Types/API:** use `app_sm_state_t` values `SM_MUTED, SM_READY_MUTED, SM_RAMP_UP, SM_RUNNING, SM_RAMP_DOWN, SM_SWAP_WAIT, SM_FAULT_MUTED`. Use `app_sm_event_t` values `SM_EV_PROTECTION_VALID, SM_EV_PROTECTION_INVALID, SM_EV_CONFIG_VALID, SM_EV_CONFIG_INVALID, SM_EV_START, SM_EV_STOP, SM_EV_SWAP_REQUEST, SM_EV_RAMP_DONE, SM_EV_SWAP_ACK, SM_EV_SWAP_FAIL, SM_EV_FAULT`. `app_sm_t` contains `app_sm_state_t state`, `bool protection_valid, config_valid`, and `app_sm_pending_t pending` with `SM_PENDING_NONE, SM_PENDING_SWAP, SM_PENDING_FAULT`. API: `void app_sm_init(app_sm_t *)`, `int app_sm_step(app_sm_t *, app_sm_event_t)`. Null/unknown event returns -1 and does not change state.
**Test:** committed, unregistered `host/tests/test_app_state_machine.c`. Register, verify missing-function baseline failure, then implement. Cover start before each prerequisite, valid start/ramp completion, stop ramp, swap round trip/failure, config/protection invalidation while running, `FAULT` from `SWAP_WAIT`, `FAULT` from `RAMP_UP`, and a pending fault surviving config/protection invalidation during `RAMP_DOWN` before `RAMP_DONE`. In `FAULT_MUTED`, verify validity events update flags but START, RAMP_DONE, SWAP_ACK/FAIL, and every other event leave the state fault-muted; verify `app_sm_init` returns to MUTED with both flags false. Also cover invalid event/null.
**Limit:** 30–80 production LOC. No FreeRTOS, GPIO, NVS or ramp execution. Reference AGENTS S2/S7; state machine only requests transitions, caller ramps audio. Three attempts maximum; honest commands/results and diff only.
