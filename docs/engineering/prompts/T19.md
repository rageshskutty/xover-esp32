# T19 — Fail-closed application state machine

**Objective:** implement deterministic transitions for mute, run, swap and fault lifecycle. The caller executes the required gain ramps and owner acknowledgments.
**Paths:** `firmware/main/internal/app_state_machine.c`, `firmware/main/internal/app_state_machine.h`, `host/tests/test_app_state_machine.c`, host test registration only.
**States:** `SM_MUTED`, `SM_READY_MUTED`, `SM_RAMP_UP`, `SM_RUNNING`, `SM_RAMP_DOWN`, `SM_SWAP_WAIT`, `SM_FAULT_MUTED`.
**Events:** protection-valid/invalid, config-valid/invalid, start, stop, swap-request, ramp-done, swap-ack, swap-fail, fault. Store current state, protection/config validity, and pending ramp-down reason.
**Transitions:** initialize MUTED with both validity flags false. START enters RAMP_UP only from READY_MUTED when both flags are true. RAMP_DONE enters RUNNING only if both remain true; otherwise enter RAMP_DOWN. STOP from RUNNING/RAMP_UP enters RAMP_DOWN. SWAP_REQUEST from RUNNING enters RAMP_DOWN with pending swap; from READY_MUTED enters SWAP_WAIT. RAMP_DONE from RAMP_DOWN enters SWAP_WAIT for pending swap, FAULT_MUTED for pending fault, otherwise READY_MUTED iff protection and config remain valid, else MUTED. SWAP_ACK from SWAP_WAIT returns READY_MUTED iff both flags remain true. SWAP_FAIL from SWAP_WAIT returns READY_MUTED iff the old graph remains valid, else MUTED. Invalidating either prerequisite while ramping/running begins or continues RAMP_DOWN. FAULT from active/ramping state begins RAMP_DOWN with pending fault; from a muted state enters FAULT_MUTED. FAULT_MUTED is terminal for this helper. No event may enter RUNNING without both validity flags.
**Types/API:** use `app_sm_state_t` values `SM_MUTED, SM_READY_MUTED, SM_RAMP_UP, SM_RUNNING, SM_RAMP_DOWN, SM_SWAP_WAIT, SM_FAULT_MUTED`. Use `app_sm_event_t` values `SM_EV_PROTECTION_VALID, SM_EV_PROTECTION_INVALID, SM_EV_CONFIG_VALID, SM_EV_CONFIG_INVALID, SM_EV_START, SM_EV_STOP, SM_EV_SWAP_REQUEST, SM_EV_RAMP_DONE, SM_EV_SWAP_ACK, SM_EV_SWAP_FAIL, SM_EV_FAULT`. `app_sm_t` contains `app_sm_state_t state`, `bool protection_valid, config_valid`, and `app_sm_pending_t pending` with `SM_PENDING_NONE, SM_PENDING_SWAP, SM_PENDING_FAULT`. API: `void app_sm_init(app_sm_t *)`, `int app_sm_step(app_sm_t *, app_sm_event_t)`. Null/unknown event returns -1 and does not change state.
**Test:** committed, unregistered `host/tests/test_app_state_machine.c`. Register, verify missing-function baseline failure, then implement. Cover start before each prerequisite, valid start/ramp completion, stop ramp, swap round trip, config/protection invalidation while running, fault ramp, terminal fault, invalid event/null.
**Limit:** 30–80 production LOC. No FreeRTOS, GPIO, NVS or ramp execution. Reference AGENTS S2/S7; state machine only requests transitions, caller ramps audio. Three attempts maximum; honest commands/results and diff only.
