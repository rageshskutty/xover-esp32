# T07a4 — SOS response evaluation tests

**Objective:** add test-only evidence that the existing `dsp_sos_eval` produces expected complex responses. No production implementation.
**Dependencies:** T07a3 accepted. Existing API: `dsp_err_t dsp_sos_eval(const dsp_sos_t *s, size_t n_sections, double fs_hz, double f_hz, double *re, double *im);` from `firmware/components/dspblocks/include/dspblocks.h`.
**Paths:** `host/tests/test_sos_response.c`, host test registration only.
**Test contract:** for each frequency 10, 1000, and 20000 Hz at fs=48000, evaluate one SOS `b=[1,0,0], a=[0,0]`; calculate dB as `20*log10(hypot(re,im))` and require 0 dB within 1e-5 dB. Evaluate `b=[0.5,0,0],a=[0,0]` at the same frequencies and require -6.020599913 dB within 1e-5 dB. Also assert successful status and finite real/imaginary outputs. Do not compare complex phase for the gain fixture.
**Execution:** add a test target linked to existing `dspblocks`, register it, run it. Since the function already exists, the expected baseline is PASS once the test is registered; this is a test-only card and has no red-before-production-code phase. Do not add production code, regenerate goldens, or add SciPy.
**Stop:** if the existing evaluator cannot represent either SOS or any exact expected value disagrees beyond tolerance, stop and report the discrepancy; do not alter implementation or tolerance.
**Evidence:** test output, command/exit code, exact files and diff-only summary. No hardware claims.
